## Overall Impression

KipiList is already above average for a mobile app — the design token system, the semantic color architecture, and the consistent component vocabulary are genuinely production-grade. The app has a clear visual identity and the DESIGN.md principles are encoded in code, not just a document.

The biggest opportunity is not in visual overhaul but in interaction maturity: missing confirmations on destructive actions, generic error messaging, and buried features that users won't discover. The design system is ready; the interaction design needs to catch up.

## What's Working

### S1. Exceptional Design Token System
`lib/core/theme/tokens.dart` defines `Spacing`, `RadiusTokens`, `DurationTokens`, `ElevationTokens` as a 4pt grid — and the entire codebase references them. No raw numbers leaked into widgets. This is rare for a mobile app and is the foundation for everything that follows.

### S2. Systematic Error Handling Pattern
Every provider uses `.when(data:loading:error:)` with a consistent triad: icon + localized message + retry button. Seen in `ListLoader` (`main.dart:552`), onboarding (`main.dart:326`), `pantry_screen.dart:54`. Users are never staring at a blank screen.

### S3. Emotionally Intelligent AI Chat UX
The chat interface anticipates user anxiety — blinking caret during streaming (`chat_bubble.dart:199`), quick-add to bypass AI latency (`chat_input_bar.dart:95`), usage banner showing remaining messages (`ai_usage_banner.dart`), teaser bubbles for non-premium users (`chat_bubble.dart:632`). Voice dictation with animated waveform. This is the most polished part of the app.

## Priority Issues

### P1: No Confirmation on Destructive Chat Actions
**Files**: `lib/app/ai/screens/ai_home_screen.dart:361`, `chat_screen.dart:43`

Tapping "new chat" immediately destroys the current session. For a free user who just used their last message, this means losing the response AND the usage credit.

**Why it matters**: Irreversible data loss. Users will be frustrated when they accidentally lose context.

**Fix**: Add a confirmation dialog when the current session has messages.

**Suggested command**: `/impeccable harden`

### P2: Generic Error Messages Throughout
**Files**: `ai_home_screen.dart:211`, `shared_paywall.dart:227`, `onboarding_slide_create_list.dart:58`, `chat_input_bar.dart`

Users see `l10n.somethingWentWrong` / `l10n.errorUnexpected` repeatedly. No actionable guidance, no retry affordance on inline errors.

**Why it matters**: Erodes trust over time. Users don't know what to do next. For a paywall, a generic error is a lost conversion.

**Fix**: Map known error types to specific messages ("check your connection", "try again in a moment"). Log specifics to Sentry, show user-actionable text.

**Suggested command**: `/impeccable clarify`

### P2: Paywall Load Failure Lacks Actionable Guidance
**File**: `lib/app/settings/widgets/shared_paywall.dart:166-184`

When RevenueCat packages fail to load after retry, the paywall shows a generic failure with no "try again" button or timeout suggestion.

**Why it matters**: The paywall is the monetization funnel. A dead end here is a direct revenue loss.

**Fix**: Add a retry CTA when `_loadFailed` is true. Consider a fallback that shows cached/estimated pricing.

**Suggested command**: `/impeccable harden`

### P3: No Confirmation When Clearing Purchased Items
**File**: `lib/app/lists/list_screen_body.dart:169`

`_clearPurchased()` deletes all purchased items silently — no dialog, no undo.

**Why it matters**: Accidental tap loses shopping history. Especially painful after a long shopping session.

**Fix**: Add a confirmation dialog matching the `_deleteSelected()` pattern (lines 117-142).

**Suggested command**: `/impeccable harden`

### P3: Market Mode is Undiscoverable
**File**: `lib/app/ai/screens/ai_home_screen.dart:384-478`

Market mode (DraggableScrollableSheet for in-store use with progress tracking) is buried inside a PopupMenuButton submenu. It's a core differentiator users won't find.

**Why it matters**: The app ships a genuinely useful in-store shopping feature that most users will never know exists.

**Fix**: Promote to a primary action — dedicated FAB or bottom bar button — or add an onboarding tooltip pointing to it.

**Suggested command**: `/impeccable shape`

## Persona Red Flags

**Alex (Power User)**: No batch price editing. No keyboard shortcuts on tablet. No list duplication/templates. Market mode buried despite being ideal for power use.

**Jordan (First-Timer)**: Onboarding is solid overall. "Skip" button on create-list slide skips directly to paywall — user sees a payment screen without having done anything. This likely bounces users who haven't experienced value yet.

**Sam (Accessibility)**: Good foundations — `ExcludeSemantics` on decorative elements, `Semantics` wrapping on plan tiles, `MediaQuery.disableAnimations` respected. Potential issue: the streaming blinking caret could trigger photosensitive epilepsy even with the `reducedMotion` check. Consider non-blinking indicator or slower blink rate by default.

**Casey (Mobile/Distracted)**: Voice dictation, quick-add, large touch targets all excellent for one-handed use. Potential concern: the AI tab packs both a list progress strip AND the chat, which could feel crowded on screens under 360dp width.
