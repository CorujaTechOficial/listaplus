## Anti-Patterns Verdict

**LLM assessment**: The snackbar system doesn't look AI-generated — it follows standard Material 3 patterns. The anti-pattern here isn't "looks AI" but "feels unfinished." The theme sets shape + elevation but misses backgroundColor, contentTextStyle, and actionTextColor, leaving every snackbar to use indifferent M3 defaults. The result is a system that works mechanically but communicates nothing through its visual language.

**Deterministic scan**: Skipped — Flutter codebase, not HTML/CSS. Detector returned empty as expected.

## Overall Impression

KipiList has ~67 snackbars across 34 files, covering every expected type (error, success, info, warning, celebration, prompt). The implementation is functional and most messages are properly localized. The core problem is that every snackbar looks the same: Material 3 gray background with default text, regardless of whether it's a celebratory first-item-added, a critical purchase error, or a routine clipboard copy. Two snackbars have custom colors — and they picked different approaches (one uses `error`, the other uses `primary` for success). No theme-level colors exist. The system has no visual vocabulary. The biggest opportunity: a 3-color semantic system (error/success/info) set once in the theme, applied everywhere.

## What's Working

1. **Undo actions are well-placed.** 5+ snackbars offer Undo (item removal, recipe deletion, meal deletion, pantry restock). This is the best pattern in the system and shows real product thinking.

2. **Localization coverage is strong.** Nearly all messages go through `AppLocalizations.of(context)`. Only one hardcoded Portuguese string was found (`ai_chat_panel.dart:372`).

3. **The `showUniqueSnackBar` utility exists.** It correctly clears before showing. The problem is it's only used in 1 file (`shopping_item_tile.dart`). The pattern is right — it just needs wider adoption.

## Priority Issues

### [P1] No semantic color coding for snackbar types

**What**: 65 of 67 snackbars use the default Material 3 background regardless of type. Error, success, info, warning, and celebration all look identical. Only `meal_day_card.dart:631` sets `backgroundColor: colorScheme.error` and `meal_planner_screen.dart:132` sets `backgroundColor: colorScheme.primary`.

**Why it matters**: Users can't distinguish severity at a glance. An error about a failed purchase looks identical to a success confirmation. This increases cognitive load and reduces trust — if everything looks the same, nothing feels important.

**Fix**: Add semantic background colors to `SnackBarThemeData`:
- Error: `colorScheme.error` + white text
- Success: `colorScheme.primaryContainer` or a success green
- Info/warning: current default or a muted surface

And either create named helper constructors or enforce via a utility.

**Suggested command**: `/impeccable colorize snackbars`

### [P1] No background/text colors in snackBarTheme

**What**: `app_theme.dart:387-393` sets only `behavior`, `shape`, `elevation`. Missing: `backgroundColor`, `contentTextStyle`, `actionTextColor`, `closeIconColor`, `dismissDirection`.

**Why it matters**: Without theme defaults, every snackbar is a blank canvas. The brand's confidence green, premium amber, and semantic colors never appear. This is the root cause of the visual uniformity problem.

**Fix**: Extend `snackBarTheme` with a full set of defaults based on KipiList's palette from DESIGN.md.

**Suggested command**: `/impeccable polish snackbars`

### [P1] Inconsistent snackbar clearing pattern

**What**: Three patterns coexist:
- `showUniqueSnackBar` (clears then shows) — only in `shopping_item_tile.dart` (3 calls)
- `clearSnackBars()` + `showSnackBar()` — in `pantry_add_sheet.dart` and `pantry_screen.dart` (2 calls)
- Bare `showSnackBar()` — everywhere else (~62 calls)

**Why it matters**: Rapid consecutive snackbars stack, creating a backlog that plays out slowly. Users see stale messages or get confused by multiple overlapping snackbars.

**Fix**: Either make `showUniqueSnackBar` the standard across the app, or add the clearing behavior to the theme with `showSnackBar` override.

**Suggested command**: `/impeccable adapt snackbars`

### [P2] Duration inconsistency

**What**: Duration values found: 1s, 2s, 3s, and unspecified (default ~4s). No pattern:
- `catalog_home_screen.dart`: 1s (very short)
- `chat_bubble.dart`: 2s (clipboard copy — good)
- `list_screen_body.dart`: 3s (celebration — reasonable)
- Most others: default Material duration

**Why it matters**: 1s is too short for most users to read, especially on mobile in bright sunlight. Inconsistent durations feel unpredictable — users don't know how long they have to act on an Undo.

**Fix**: Standardize: info = 2s, success = 2s, error with action = 5–6s, error without action = 4s.

**Suggested command**: `/impeccable layout snackbars`

### [P2] Redundant explicit property overrides

**What**: `behavior: SnackBarBehavior.floating` is set explicitly in 5+ files even though the theme already sets it. `shape` is re-set in `ai_chat_panel.dart:382`.

**Why it matters**: Redundant code creates maintenance burden and suggests developers aren't trusting the theme. If the theme changes, overridden properties won't follow.

**Fix**: Remove all duplicate `behavior` and `shape` overrides from individual snackbar calls.

**Suggested command**: `/impeccable distill snackbars`

### [P2] Raw error messages exposed to users

**What**: `ai_home_screen.dart:187` and `ai_chat_panel.dart:185` show `e.toString()` directly in snackbars.

**Why it matters**: Raw exception messages can contain technical details, file paths, or English-only text. They're unpredictable and break the localized UX.

**Fix**: Wrap all raw exceptions in a localized fallback message. Log the original to console/crashlytics.

**Suggested command**: `/impeccable harden snackbars`

### [P3] Hardcoded non-localized string

**What**: `ai_chat_panel.dart:~372`: `'A IA está aprendendo suas preferências!'` — hardcoded Portuguese.

**Why it matters**: Breaks the project's 86-locale system. Will show Portuguese to every user regardless of locale. Has a `// TODO: l10n` comment.

**Fix**: Add to `app_en.arb` and use `AppLocalizations`.

**Suggested command**: `/impeccable harden snackbars`

### [P3] `meal_planner_screen.dart` uses `primary` color for success

**What**: Line 132 sets `backgroundColor: Theme.of(context).colorScheme.primary` (green) for a success message.

**Why it matters**: While green is appropriate for success, using the primary brand color conflates brand identity with semantic state. Success should use a success-container tone, not the primary action color.

**Fix**: Use `colorScheme.primaryContainer` or a dedicated success semantic color.

**Suggested command**: `/impeccable colorize snackbars`

## Persona Red Flags

### Alex (Power User)
- 67 snackbars, zero with a close/dismiss button. Must wait for auto-dismiss or perform an action.
- The `showUniqueSnackBar` not being universal means snackbars can stack — frustrating when trying to work fast.
- No notification history — if Alex dismisses or misses a snackbar, the information is gone permanently.

### Jordan (First-Timer)
- Some errors show raw `e.toString()` messages that are technical and confusing.
- The hardcoded Portuguese snackbar in `ai_chat_panel.dart` will confuse non-Portuguese speakers.
- Duration inconsistency: some messages disappear in 1s before Jordan can finish reading.

### Sam (Accessibility-Dependent)
- No semantic color differentiation between error/success/info means color-reliant cues are absent.
- No `closeIconColor` or `actionTextColor` set in theme — contrast relies on Material defaults.
- Error snackbars don't consistently use error colors, so screen reader users can't get visual reinforcement.

## Minor Observations

- `ai_chat_panel.dart:372` celebration snackbar uses a `Row` with `Icon(Icons.auto_awesome)` + `Text(...)` as `content`. This is a nice touch but inconsistent — no other celebration/positive snackbar uses this pattern.
- `list_screen_body.dart:273` celebration snackbar uses `Icons.star`. Two different celebration icons — pick one.
- `meal_day_card.dart` is the only file that correctly uses `colorScheme.error` — it's the model pattern.
- Catalog snackbars (1s duration) are the fastest in the app. This may be intentional (transient confirmations) but 1s is below recommended minimum for readability.
- The `showUniqueSnackBar` utility takes `Widget content` instead of `String message` — this gives flexibility for icon rows but could also encourage inconsistent content patterns.
- No snackbar animation customization — all use default slide-from-bottom.

## Questions to Consider

- "If every snackbar looks the same, what communicates urgency when a purchase fails?"
- "Should we define 3 semantic snackbar types (error/success/info) in a single `showKipiSnackBar(context, type, message, action)` utility, or set colors in the theme and rely on per-call overrides?"
- "Is there a case for a notification history / log for users who miss transient messages?"
- "The celebration snackbar (star icon) is unique — is this deliberate brand personality worth extending to other positive moments?"
